# Cross-song recognition v11 implementation plan

**Goal:** Improve recognition beyond the Can Can calibration: instrumental short Holds, false Follow phrases and defensible missed supports. Preserve all originals and twelve prior custom maps; publish only six new test IDs. No player builds.

**Architecture:** Keep source measurements, gesture classification, native compilation and route choreography separate. Extend existing pure classifiers with measured articulation/context rather than identity or reference-timestamp lookups. Retain successful V10 recognition when a broader rule is not supported. Use one manifest-driven study/publisher for future iterations instead of duplicating version-specific evaluation code.

**Baseline:** `fd39ed4`, V10 with experimental short supports explicitly enabled, actual Unity PCM, fixed evidence, source speed and .6s preroll. The ten prior recordings are all known tuning/regression data now. Add Ode to Joy, Canon in D and Aaj Ki Raat to calibration; select Bajo El Sol and Baby Shark by aggregate counts only for a new heldout check.

**Design choices:** Diagnose source coverage before retraining. The V10 voice-dependent classifier covers most Für Elise candidates but rejects all true short Holds; removing voice features or naive retraining regresses known songs. Test supplemental instrumental/melody-relative context with grouped cross-song validation. Verify legacy and new Follow against independent articulated notes: an irregular five-attack spectral signature can be false when omitted regular notes reveal a staccato run. A phrase need not change pitch to be a legitimate moving support, so pitch constancy alone is not a veto.

**Metrics:** Short Hold <=.45s on both sides; onset/end <=80ms; IoU>=.5. Follow onset<=80ms, end<=150ms, IoU>=.5. Maximum-cardinality one-to-one matching. Track misses and extras, all-event F1, geometry and actual gameplay separately; do not weaken criteria to improve counts.

## Integrity and evaluation boundaries

Preserve the four pre-existing user changes, original404 data/audio files, all prior custom maps/metas, music/manual score and character assets. Inference receives only actual audio-derived evidence and measured pulse, never reference annotations or study roles. Calibration labels are read only by separate training/evaluation. The two heldout recordings must not be inspected for event times, features or errors before the recorded freeze. After evaluation they are known and cannot be called unseen again. Paid generation, network audio uploads, model downloads, package changes and player builds are outside this iteration.
