# Калибровка генератора: Unstoppable, v5

В текущем тестовом уровне **Unstoppable · тест генератора** распознаны семь
длинных плиток из четырнадцати и оба проката. Лишних Hold и Follow нет.
Все девять интервалов проходят проверку обеих границ с допуском 150 мс и
пересечением `IoU >= 0,5`. Оригинальная карта и исходная музыка не изменены.
Тестовый уровень имеет собственную карту и ID `UnstoppableGeneratorTest`.

Это улучшение приближает временную разметку к оригиналу, но **карта пока не
идентична**: семь Hold ещё пропущены, автоматических BigJump — ноль против
семи в эталоне. Горизонтальные маршруты прокатов также отличаются.

## Как получается карта

`pcm-vocal-phrase-chart-v5` получает декодированный PCM и независимые
измерения этого же аудио. Название песни, её ID, эталонные таймкоды и исходная
карта не участвуют в генерации. Эталон читается отдельно при оценке.

1. Спектральный анализ с окном Hann 1024 и шагом около 10 мс находит реальные
   атаки. Усредняются модули спектров отдельных каналов, поэтому противофазное
   стерео не уничтожает сигнал. Локальные пороги подавляют слабые и слишком
   близкие всплески.
2. По повторяющимся спектрально непрерывным артикуляциям определяется Follow.
   Измеряются границы фразы; движение по полосам задаёт самостоятельная
   игровая палитра. Подробности — [PHRASE_GENERATOR.md](PHRASE_GENERATOR.md).
3. Для Hold смешанного спектра оказалось недостаточно: фоновые инструменты
   часто маскируют ведущий голос. Локальный UVR Kim Vocal 2 выделяет вокал;
   Spotify Basic Pitch измеряет его высоту, активность и атаки. Ищется
   непрерывный нисходящий распев либо протяжная опорная нота с нисходящим
   окончанием. Одна постоянная высота не обязательна: например, первый Hold
   содержит последовательность F4 → E♭4 → C4.
4. Конец вокальной фразы уточняется по её RMS-огибающей и ближайшей измеренной
   спектральной атаке. Подтверждённые Hold/Follow подавляют обычные прыжковые
   плитки внутри интервала. Входы, найденные по вокалу и пропущенные смешанным
   спектральным детектором, сохраняются отдельно; ложные вокальные кандидаты
   не добавляются в общую сетку прыжков.

Вокальная модель запускается **только при локальной подготовке данных**.
Editor читает компактный проверяемый `.voice.json`; игра проигрывает готовую
карту и не запускает ML или спектральный анализ. Без вокального кэша остаётся
ветка v4. Автоматическое присвоение BigJump по одному временному промежутку
не включено: оно давало слишком много неверных больших плиток.

Отчёты сохранены отдельно: [baseline.json](baseline.json), [v3.json](v3.json),
[v4.json](v4.json), текущий [candidate.json](candidate.json). Старый baseline
не перегенерируется новым алгоритмом.

F1 учитывает пропуски и лишние события; значение 0,81050 не означает 81%
полной идентичности уровня. В эталоне 162 элемента, 163 события и 138 основных
музыкальных входов; в v5 — 174 элемента, 180 событий и 162 входа. Это разные
представления карты: служебные маркеры, выходы и точки проката не равны новым
прыжковым плиткам. `logicalSupports` отдельно оценивает музыкальные входы.

Последняя треть начинается с 44,669388 с. Она остаётся частью этой же песни:
пороги и результаты обеих частей просматривались при доработке, а поиск
повторов анализирует запись целиком. Это **не слепая проверка и не доказательство
качества на новых песнях**.

### Длинные плитки и прокаты

| Показатель v5 | Hold | Follow |
| --- | ---: | ---: |
| В эталоне | 14 | 2 |
| Найдено / правильных / лишних | 7 / 7 / 0 | 2 / 2 / 0 |
| Recall | 0,50 | 1,00 |
| MAE начала | 19,16 мс | 5,98 мс |
| MAE конца | 37,25 мс | 22,35 мс |
| MAE длительности | 38,43 мс | 19,79 мс |
| Средний IoU совпавших интервалов | 0,93355 | 0,97920 |

Входы сопоставлены с допуском 80 мс. Отдельная строгая проверка поддержки
требует правильного типа, ошибок обеих границ не больше 150 мс и `IoU >= 0,5`.
Сопоставление взаимно однозначное; один эталонный интервал нельзя засчитать
нескольким предложениям. Пропущенные семь Hold остаются в знаменателе recall.
Поэтому средний IoU найденных Hold 0,93355 не следует распространять на все
четырнадцать: `referenceCoverageIoU` равен 0,46677.

Все девять поддержек и семь пропусков видны в
[candidate.supports.csv](candidate.supports.csv). Отдельная проверка вокального
детектора — [vocal-final-metrics.json](vocal-final-metrics.json).

Форма прокатов воспроизведена приблизительно. Согласие направления движения
для двух фраз — 36,8% и 100%; средняя ошибка координаты полосы — 0,557 и 0,276.
Эти цифры подтверждают точные временные интервалы, но не восстановление
оригинальной траектории. Разметка Theme также не восстанавливается как
отдельный оригинальный тип.

## Воспроизведение и целостность

Анализ должен получать **тот PCM, который воспроизводит Unity**. У исходного
AudioImporter уже включён Vorbis. Его настройки сохранены: декодирование WAV
в Python и `AudioClip.GetData` дают разные PCM-хеши. Поэтому Editor экспортирует
настоящие float32 little-endian сэмплы, затем CLI проверяет их метаданные и SHA.
Ослаблять проверку ради принятия другого декодирования нельзя.

| Объект | SHA-256 |
| --- | --- |
| Оригинальная карта | `277e5fd678a41323273dd786f32450291338d4edf4752d9ff83939b52548de90` |
| Исходный WAV | `7fdf15c8df324f3dff96d1992248081611f0751a2ad454013f719d15bcf91d6b` |
| Настоящий Unity GetData PCM | `88ea37d6fc9b91863509c174e1aad914cff14704e6be6d20a57b5ffe21429102` |
| Канонический digest вокальных признаков | `1087a84b2019acb19e88794e6286342e825530b8d89d30c5f619858dbc85ebae` |

Кэш адресуется хешем исходного аудиофайла и дополнительно проверяет PCM,
частоту, каналы, число сэмплов, происхождение моделей, конечность значений,
порядок времени и целостность массивов. Digest чисел использует целые int64
с точностью 1e-8, чтобы различия JSON-парсеров Unity и Python не меняли хеш.
Неверный PCM, изменённый RMS и нечисловой шаг отвергаются.

Подготовка описана в [Tools/RhythmAnalysis/README.md](../../../Tools/RhythmAnalysis/README.md).
Команда Unity: **Assets → Dancing Cats → Export selected audio PCM for vocal analysis**.
Скрипт `analyze_vocal_holds.py` принимает `--decoded-pcm` и `--decoded-metadata`;
эталонную карту он не читает. Веса, стем и промежуточные активации хранятся в
игнорируемой `Library`. В репозитории остаются CLI, лицензии, компактные
признаки и [vocal-provenance.json](vocal-provenance.json).

Использованы локальные ONNX-модели: UVR Kim Vocal 2, около 64 МБ,
и Spotify Basic Pitch, 230 КБ, Apache-2.0. Код проекта UVR распространяется
по MIT; авторы просят указывать их при использовании модели. Исходные
ссылки, фиксированные SHA и лицензии перечислены в
[THIRD_PARTY_NOTICES.md](../../../Tools/RhythmAnalysis/THIRD_PARTY_NOTICES.md).
Аудио не отправлялось в сеть; Runway не использовался. Для 67-секундной записи
измерено около 31 с CPU на выделение вокала и 1,2 с на нотный анализ.

`OriginalChartCalibration.RunChecks()` повторяет проверки и оценку;
`GenerateUnstoppableComparison()` сохраняет только отдельный тестовый вариант
с защитой оригинала по хешам. `PcmVocalIntegrationValidation.RunChecks()`
проверяет реальные GetData/кэш, детерминизм, сохранение вокальных входов,
отсутствие перекрывающихся прыжков и независимые флаги Hold/Follow.
