# Generator v12 and landing timing implementation plan

**Goal:** Improve measured gesture recognition beyond v11 and investigate the reported late landing/hit sound. Preserve every original and all eighteen existing custom maps. No player builds.

**Architecture:** Keep audio measurements, source-only gesture recognition, native map compilation and runtime presentation timing separate. Extend the existing manifest-driven paired study. Do not compensate a chart, collision, animation or sound error by shifting unrelated clocks.

**Design:** Existing local CART extensions did not transfer reliably across songs. Test a foreground-voice sequence and relative rhythmic duration for short supports, rather than repeat fixed-window threshold tuning. Independently test measured continuity/inner articulation for false legacy long Holds and additional Follow families. Compare runtime intended landing, actual contact, visual foot position and hit sound onset against the original evidence. The fifteen v11 recordings are now known calibration/regression material; do not call this iteration an unseen evaluation.

**Constraints:** Work in the existing `feature/radio-archipelago` checkout used by the running Editor. Baseline `56853c0`, v11 with explicit experimental short supports, common actual PCM/evidence/source speed and 0.6 s preroll. Musical criteria remain onset/end <=80 ms and IoU >=0.5 for short Hold (both durations <=0.45 s), onset <=80 ms/end <=150 ms/IoU >=0.5 for Follow, one-to-one matching. No source identity, annotation time, target count or reference path in inference. No paid generation, downloads, package changes, music/model or unrelated settings changes. Preserve the four pre-existing user modifications. The timing investigation proved a shipped-original DSP mismatch; the only necessary settings change is AudioManager 512/requested512, validated separately on an identical map.
