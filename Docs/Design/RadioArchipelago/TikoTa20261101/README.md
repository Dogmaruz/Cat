## Найденные причины и решения

1. Строгий валидатор обнаружил обычный разрыв 3.192744 s в непрерывном припеве. Старая sparse-политика принимает новое начало вокала или устойчивое гармоническое тело, поэтому пропускала реальные повторные атаки внутри непрерывного голоса. Добавлен отдельный source-independent `PcmMeasuredGapRecovery`: только для слишком длинных внутренних интервалов выбирает настоящую подтверждённую атаку, сохраняя старые опоры/пути/большие перелёты. По умолчанию выключен; включён только в настройках Тико-та. Нет привязки к названию/временам песни, сеточного наполнения или ослабления валидатора. Реальная максимальная обычная пауза после исправления 1.897188 s.
2. Проверка полного керамического меша на дуге нашла зазор 8.1 cm при обязательном резерве 10 cm. Только для второго острова продольный масштаб увеличен 1.18→1.20 (1.7%); такое же значение используется для source grouping. Размеры плиток, музыка, боковая ширина, камера и ландшафт сохранены. Строгая повторная геометрическая проверка прошла. Финиш: 666.8618 m → 672.8618 m → 707.6618 m, в пределах зарезервированного ровного участка.

RED-данные обоих реальных отказов и отсутствующей до реализации recovery-функции находятся в `Before/`. Новые counterexample tests, старые sparse checks и полный AudioChartGeneratorValidation прошли в живом Editor; подтверждение в `Review/generator-checks-green.json` и `Review/validation-log.txt`.
