# Подвижные механизмы на крышах — 1–2 ноября 2026

Исправлены обе антенны-тарелки на красных плоских крышах Coral Oasis. Их исходная опора начиналась на отметке h+0,68, хотя верх второго кровельного объёма был h+1,435. Вся сборка поднята на верхнюю поверхность крыши: на0,8305м и0,94375м с учётом масштаба двух домов. Тарелка, обод, стойки и приёмник сохранены вместе. `Coral-before-dish.png` и `Coral-remounted-dish.png` сняты в настоящем Unity с одинаковой камерой.

На каждом из трёх готовых островов теперь четыре подвижных механизма, всего12. На первом — развилки антенн трёх больших домов и ранее увеличенного домика; на втором — две развилки, малый приёмник башни и большое колесо со спицами; на третьем — три развилки и большой калибровочный приёмник. Скорости55–135°/с, направления различаются. Основания, мачты, трубы и крыши остаются неподвижны.

Из прежних пространственных батчей извлечена только точная исходная геометрия головок. Она перенесена в отдельные жёсткие дочерние узлы с правильным центром вращения. Внутри затронутых батчей остальные координаты/грани/UV/цвета/сглаживание сохранены точно; остальные270/251/263меша соответственно не изменены. Новый свет, глобальные шейдерные эффекты, физика, отдельные Update на деталях и копии материалов не добавлялись. Сохранены большой домик первого острова, сто кристаллов третьего, новая вода, все музыкальные карты/маршруты/камеры/персонажи/облака/финиш.

`IslandRooftopMotion` — один принадлежащий сцене помощник, который хранит четыре Transform/исходные позы/оси/скорости. В существующем `IslandStagePresentation.LateUpdate` он получает дельту того же источника и ограничения, что и остальная презентация: unscaledDeltaTime≤0,1с, ноль при ClonePhase.Paused. Механизмы продолжают жить в меню/Results, пока существует 3D-представление острова. Deactivate/rebind восстанавливает исходные позы и очищает ссылки. Зависимость явная: `IslandStageDefinition.RooftopMotionJson`. Имена, центры и оси проверяются при Configure; поиск по иерархии выполняется только при привязке.

Новые дочерние Renderer используют существующие общие Metal/Architecture материалы. `installation.json` содержит настоящие числа новых Renderer/слотов: по4Renderer,8/6/7слотов материалов. В `native-motion.json` одноимённые неиспользуемые поля отчёта установки оставлены нулевыми; они не означают отсутствие добавленных Renderer. Движущиеся узлы исключены из BatchingStatic. Штатные Unity bounds, depth и shadow passes следуют обычным Transform, без отдельной реализации в шейдере.

Проверено после окончательного импорта в Unity6000.5.5f1:

- `rooftop-install` и `rooftop-review`: PASS. Четыре головки на остров, корректные общие материалы и привязки к их сохранившимся источникам. За1,2с все головки поворачиваются минимум на66–90°, центры не смещаются; нулевая дельта замораживает позы; Dispose возвращает исходные повороты. После прогрева2000Tick дают0managed bytes. Статические крыши/здания неподвижны, коллайдеров/Rigidbody на механизмах нет.
- Три реальные позы0/0,6/1,2с для каждого острова сохранены PNG. Это изолированные виды Unity-prefab с тем же runtime-помощником; полный музыкальный прогон не проводился.
- Единственный полностью опустевший прежний Coral-батч сохранён как пустой Transform с прежним именем. Его недействительный MeshRenderer и ровно одна устаревшая привязка материала удалены. Другие прежние prefab-override сохранены точно; подтверждение `semantic-asset-diff.json` и `obsolete-override-removal.json`.
- После очистки `rooftop-empty-bindings` не находит пустых импортированных MeshFilter/Renderer. Geometry checker не ослаблялся.
- Повторные `island-abyss-checks`, `coral-checks`, `moon-checks`: все PASS. Карты, физический коридор, высоты, материалы и разрешённая сохранность предыдущих островов подтверждены. `moon-open` оставил чистый Edit Mode.
- По сравнению с состоянием после принятой воды изменились ровно9из405защищённых файлов:3FBX,3prefab и3определения. В каждом определении добавлена только ссылка на manifest. Все остальные396, включая семь материалов воды, прежние. Список точных SHA — `protected-changes.json`.

Авторинг и замороженные входы: `ArtSource/RadioArchipelago/Islands/RooftopMechanisms20261101/`. `prepare_rooftops.py` работает в отдельном background Blender и пишет только STAGING; Unity-файлы он не перезаписывает. В Before сохранены входные FBX, определения, prefab и исходные интеграционные скрипты. Контроль геометрии и подтверждение установленных SHA — `source-emerald.json`, `source-coral.json`, `source-moon.json`.

Примечание для повторного авторинга: Unity при сохранении первого определения дополнительно выписывает ранее не сериализованные значения по умолчанию `FinishExitYaw:-53`, `SparseCloudSteps:0`, `CloudStepRanges:[]`. В итоговом файле эти три новых строки убраны, чтобы разница с исходником была только в `RooftopMotionJson`; значения при загрузке те же. При повторном Install нужно сохранить эту минимальную сериализацию перед проверкой точного SHA. Старые исходные определения сохранены в Before.
